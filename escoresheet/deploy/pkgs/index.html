Windows

Version @DESKTOP_VERSION@ · 64-bit

Download and run the installer. Windows may show a SmartScreen notice for a new download: More info → Run anyway.

It installs for all users and asks once for an administrator: that lets the tablets on the local network through Windows Firewall. The first start

The app is not notarized by Apple (that needs a paid Apple developer account), so macOS blocks it the first time. Open it once and close the message, then System Settings → Privacy & Security → Open Anyway. On macOS 14 and older: right-click the app → Open. Or in Terminal:

xattr -dr com.apple.quarantine "/Applications/OpenVolley eScoresheet.app"

Start it from Applications: from there it updates itself. The tablet Wi-Fi of the Windows and Linux app is not available on macOS: connect the tablets through the venue's Wi-Fi, a travel router or macOS Internet Sharing.

Linux

Version @DESKTOP_VERSION@ · amd64

Debian, Ubuntu, Mint: one command adds the signed APT repository (it checks the key fingerprint first) and installs the app. Running it again is harmless.

curl -fsSL https://get.openvolley.app/install.sh | sudo sh

Read it first if you like: install.sh

Start it from the app menu (OpenVolley eScoresheet) or with @DEB_PACKAGE@. Headless relay for the tablets only: @DEB_PACKAGE@ --server-only. It updates itself; sudo apt update && sudo apt upgrade works too.

Set up APT by hand, check the key 
curl -fsSL https://get.openvolley.app/apt/openvolley.gpg | sudo tee /usr/share/keyrings/openvolley.gpg >/dev/null
echo 'deb [arch=amd64 signed-by=/usr/share/keyrings/openvolley.gpg] https://get.openvolley.app/apt stable main' | sudo tee /etc/apt/sources.list.d/openvolley.list
sudo apt update && sudo apt install @DEB_PACKAGE@

Check the key before trusting it: gpg --show-keys /usr/share/keyrings/openvolley.gpg must show the fingerprint below. Installed the .deb from GitHub before (package openvolley-e-scoresheet)? sudo apt install @DEB_PACKAGE@ replaces it.

Signing key: OpenVolley packages <packages@openvolley.app>, ed25519 (openvolley.asc)

AB46 9DA8 DC3E C90F 8057 320D 285B 18D7 6C16 B82C

Fedora, openSUSE, any distribution: Flatpak 
flatpak install --user https://get.openvolley.app/flatpak/com.openvolley.escoresheet.flatpakref

Start it from the app menu (OpenVolley eScoresheet) or with flatpak run com.openvolley.escoresheet. Flatpak keeps it up to date (flatpak update or the software centre); this copy does not update itself. The signed repository (its key is in the file): openvolley.flatpakrepo.

The tablet Wi-Fi and Bluetooth network need NetworkManager on the computer; the tray icon needs a tray (GNOME: the AppIndicator extension). Matches of an APT install are not seen by the Flatpak: back them up and restore them in the app.

Arch Linux, Manjaro, EndeavourOS: pacman

A signed pacman repository: pacman installs the app and brings every update with sudo pacman -Syu; this copy does not update itself. Set it up once:

1. Trust the repository key

curl -fsSLO https://get.openvolley.app/arch/openvolley.gpg
sudo pacman-key --add openvolley.gpg
sudo pacman-key --lsign-key @PACMAN_FPR@

Check the key before trusting it: gpg --show-keys openvolley.gpg must show the fingerprint below.

2. Add the repository

At the end of /etc/pacman.conf (for example with sudo nano /etc/pacman.conf):

[openvolley]
SigLevel = Required DatabaseRequired
Server = https://get.openvolley.app/arch/$arch

3. Install

sudo pacman -Syu openvolley-escoresheet-bin

Start it from the app menu or with openvolley-escoresheet. For the tablet Wi-Fi also install networkmanager and dnsmasq.

The same packages as the AUR's (-bin: the released .deb, repackaged), built and signed here. Signing key: OpenVolley pacman repository <packages@openvolley.app>, ed25519 (openvolley.gpg)

@PACMAN_FPR_GROUPED@

How updates work

Android

F-Droid keeps the app up to date: on Android 12 and newer it installs updates by itself, with no tap, while the tablet is idle (never while the scoreboard keeps the screen on). Android 7 to 11 shows one Update tap. On a scorer tablet use the F-Droid client 2.0 or newer, and in F-Droid set Settings → app auto-updates → Only on Wi-Fi. Installed from f-droid.org? It builds each version some days after it appears here; add this repository in F-Droid to get it right away.

Installed the APK from the browser? Open the app in F-Droid once and tap Update: from then on F-Droid updates it. Without F-Droid, OpenVolley can tell you about a new version instead, if you say yes when it asks (about once a day it reads the version list on this site, never during a match; nothing else is sent). It never installs anything itself. Point Hub on the scoreboard's tablet updates itself from the board.

Windows, Linux and macOS

From version 2.2.0 the OpenVolley and OpenBeach desktop apps update themselves: they download the update in the background and install it when you quit the app, never during a match. Windows asks once for an administrator per update. Linux installed with the command above updates in the background and then restarts into the new version by itself, on the home screen and never during a match. macOS: the same, for the app started from Applications; it asks for an administrator only when the app's folder is not yours to write (Homebrew leaves the updates to the app). Version 2.1.x and older: install 2.2.0 once by hand (Linux: sudo apt update && sudo apt upgrade).

A Flatpak, Snap, Arch (pacman) or AUR copy never updates itself: flatpak update, the Snap Store, sudo pacman -Syu or yay -Syu brings the new version. Point Hub's desktop app never updates itself: its package manager, or the next installer, does.
